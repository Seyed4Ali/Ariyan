# بررسی ریپازیتوری‌های مالی و هوش مصنوعی برای Ariyan

تاریخ بررسی: ۱۲ نوامبر ۲۰۲۶. مبنا: README فعلی شاخهٔ پیش‌فرض و مشخصات عمومی GitHub هر مخزن. پروژه‌ها نصب یا به حساب متصل نشده‌اند؛ قابلیت‌های زیر توصیف مستندات خود پروژه‌ها هستند، نه نتیجهٔ ممیزی کامل کد یا آزمون سودآوری.

## انتخاب برای پروژهٔ ما

برای چرخهٔ سریع متاتریدر، موتور سبک محلی، مدیریت سفارش پایدار و دادهٔ تازه اولویت دارند. پیشنهاد: استفاده از الگوهای مدیریت سفارش و پژوهش Aurum، روش‌های بک‌تست و کنترل خطای Freqtrade، سپس دادهٔ تکمیلی OpenBB. مدل Kronos پس از سنجش روی دادهٔ همین بروکر می‌تواند فیلتر آزمایشی باشد. تحلیل چندایجنتی و پژوهش خبر باید بیرون از مسیر دریافت تیک و ارسال سفارش اجرا شود؛ طولانی‌شدن آن‌ها نباید اجرای سفارش و حد ضرر را معطل کند. این رتبه‌بندی پیشنهاد معماری برای Ariyan است.

## نکات تصمیم‌گیری

### Kronos

مدل‌های small/base در README با سقف زمینهٔ ۵۱۲ کندل معرفی شده‌اند. تبدیل پیش‌بینی کندل به ورود معاملاتی نیازمند آزمون هزینه، کالیبراسیون و قواعد ریسک جداگانه است. آموزش روی بورس‌های متعدد، به‌خودی‌خود کارایی روی EURUSD/GOLD/BITCOIN همین بروکر را ثابت نمی‌کند. مقدار pushed_at در بررسی GitHub برابر ۱۳ آوریل ۲۰۲۶ بود؛ این زمان آخرین push مخزن است و جای بررسی تغییرات تک‌تک فایل‌ها را نمی‌گیرد.

### TradingAgents و Vibe-Trading

این دو برای تحقیق و تصمیم قابل توضیح مناسب‌اند. برای Ariyan، خروجی ساختاریافتهٔ آن‌ها می‌تواند زمینهٔ سشن یا فرضیهٔ قابل‌آزمایش تولید کند. داده باید زمان انتشار داشته باشد و مدل نباید دادهٔ بعد از زمان تصمیم را در بک‌تست ببیند. درخواست‌های مدل و ابزارهای جست‌وجو به چرخهٔ میلی‌ثانیه‌ای یا تیک وابسته نشوند.

### day-trader-skill

«۱۰ هزار بار بازپخش» بازنمونه‌گیری مسیرها تحت فرض‌های مدل است؛ معادل ۱۰ هزار معاملهٔ مستقل واقعی نیست. داده‌های نمونه و اتصال معرفی‌شده عمدتاً برای سهام آمریکا و Alpaca هستند. برای پروژهٔ ما باید منبع داده، هزینه، سشن، گام قیمت و لات MT5 جایگزین شوند.

### Aurum: تفاوت مهم با توضیح قدیمی

README فعلی نام Aurum v2 دارد. خود نویسنده می‌گوید ادعاهای سود سالانهٔ ۸۰–۱۲۰٪ نسخهٔ اول پشتوانه نداشته و حذف شده‌اند. در ارزیابی فعلی نیز مزیت آماری اثبات‌شده‌ای برای استراتژی‌ها ادعا نمی‌شود. یادداشت نسخهٔ قدیمی، نشت آینده، بک‌تست غیرقابل اتکا و مشکلات ریسک اجرای زنده را شرح می‌دهد. بنابراین فایل‌های legacy و اکسپرت grid/martingale به‌عنوان موتور اجرای Ariyan وارد نشوند. ارزش نسخهٔ فعلی برای این پروژه در روش پژوهش و مهندسی اجرای سفارش است.

### آمار رشد و مجوز

رشد «این هفته» و ترتیب فهرست از یک عکس لحظه‌ای GitHub قابل تأیید نیست. برای آن باید ستاره‌ها در ابتدا و انتهای هفته با زمان و منطقهٔ زمانی مشخص ثبت شوند. TradingAgents در این بررسی ۱۲۲٬۱۶۰ ستاره داشت؛ عدد ۱۱۳ هزارِ متن ارسالی وضعیت فعلی نیست.

مشخصات GitHub، Freqtrade را GPL-3.0 و FinceptTerminal را AGPL-3.0 معرفی می‌کند. برای استفادهٔ مستقیم از کد، فایل LICENSE همان نسخه باید جدا بررسی شود. README فعلی OpenBB از Apache-2.0 نام می‌برد، ولی تشخیص خودکار GitHub در این snapshot مقدار NOASSERTION داشت؛ این اختلاف به معنی تأیید یک تفسیر حقوقی نیست. در اصلاح فعلی Ariyan کدی از این یازده مخزن کپی نشده است.

## ترتیب پیشنهادی توسعه

۱. تثبیت چرخهٔ قیمت → سیگنال → بررسی ریسک → سفارش → تطبیق → خروج؛ سنجش تأخیر، ثبت دلیل هر رد و جلوگیری از سفارش تکراری.

۲. جمع‌آوری نمونهٔ دموی تازه و آزمون خارج از نمونه با اسپرد/کارمزد/لغزش؛ مقایسهٔ پروفایل سریع با نسخهٔ مبنا. سریع‌ترشدن به‌تنهایی معیار پذیرش استراتژی نیست.

۳. افزودن پژوهش جدا با الگوهای Aurum/Freqtrade و دادهٔ مکمل OpenBB؛ هیچ مدل یا گزارش نباید دروازهٔ قطعی ریسک را دور بزند.

۴. آزمایش Kronos به‌عنوان فیلتر اختیاری و سنجش افزودهٔ واقعی آن. پس از آن، گزارش سشن با TradingAgents یا Vibe-Trading و خلاصهٔ روزانه اضافه شود.
